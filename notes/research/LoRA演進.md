2020年左右，參數量逐漸突破百億、千億，因此浮現出一些問題
- 記憶體崩潰: 老方法是全參數微調
- 成本過高: GPU算力不夠
- 儲存空間爆炸: 對需求微調，不同客戶不同問題，模型儲存成本不切實際

### 想法: 降維

先前已有研究（如 Li 等人在 2018 年的研究）指出，大模型雖然參數極多（高維度空間），但當它在學習特定任務時，其實只需要在一個**非常低的分量空間（低維度空間）**進行更新就足夠了。這意味著，**模型微調時的「權重變化量」，本質上是一個低秩（Low-Rank）矩陣**

### LoRA誕生
Microsoft團隊基於上述理由建立了LoRA，概念如下:

1. 凍結原模型: 模型參數(w)固定住，所以不需要重新算參數(back prop)
2. 並聯小矩陣: 在原模型的旁邊，塞入兩個極小的低秩矩陣（稱為 A 和 B）來捕捉變化量。
3. 矩陣分解: 原本一個 d\*d 的超大更新矩陣，被拆解成 d\*r 和 r\*d的兩個小矩陣（其中 r 通常設得非常小，d >> r）。

![[Pasted image 20260908102323.png]]


### LoRA：刻意只挑 attention 層

原始 LoRA 論文在 4.2 節講得很明白，他們**只**把 LoRA 用在 self-attention 裡的 Wq,Wk,Wv,Wo​，MLP 層完全凍結不動。原因是「simplicity and parameter-efficiency」——選擇性地限制在特定矩陣，減少計算量與參數。

論文甚至做了實驗（Table 5）去比較「該把有限的參數預算放在 Wq​ 還是 Wv還是全部」，結論是同時用在 Wq,Wv 效果最好。但**MLP 層從頭到尾沒被碰過**。

### 1LoRA：反而是刻意「不挑」，全部線性層都用

1LoRA 附錄 A 講得很直接：
![[Pasted image 20260907211601.png]]

這是它的核心賣點之一，摘要裡就寫了：

> "1LoRA allows to fine-tune more evenly across layers, **instead of focusing on specific ones (e.g. attention layers)**, improving performance further."

為什麼可以這樣做？因為 1LoRA 每層只需要  d 個參數（比 LoRA 的 k+d 少很多），記憶體開銷極小，所以就算全部線性層（包含 attention 的 QKV/output，以及 MLP 的兩層）都加上 1LoRA，總記憶體用量還是可控。

### 有具體證據支持嗎？

有，論文用 LLaMA-2 13B 的實驗（Figure 4）直接證明這個差異的重要性：
![[Pasted image 20260907211043.png]]
- LoRA 因為記憶體不夠，被迫**只能**限制在 Q, K, V 三種矩陣（論文標成 "LoRA (QKV)"）
- 1LoRA 用差不多的記憶體預算，可以**同時涵蓋所有線性層**（包含 MLP）
- 結果 1LoRA 效能勝過受限的 LoRA (QKV)

### PCA 分析：不同層其實貢獻不一樣（5.2 節）

![[pca_cosine_similarity_concept.png]]

現在有三種「壓縮方向」候選人，都是拿去跟這些 PC 方向比對：

1. **Summation（1LoRA 用的）**：固定用「全部加總」的方向，也就是向量 1
2. **Random**：隨機選一個方向
3. **Learned（LoRA, r=1 學出來的）**：讓模型自己去學一個最好的方向

比對方式是算 **絕對餘弦相似度 (absolute cosine similarity)**：

- 1 = 完全同方向（這個候選方向剛好抓到這個 PC 想要的變化）
- 0 = 完全垂直、不相關（這個候選方向根本沒抓到重點）

### Figure 9 在畫什麼

- **X 軸**：主成分編號（1, 10, 100, 1000...，取 log），也就是「第幾重要的方向」
- **Y 軸**：那個候選壓縮方向跟這個 PC 的餘弦相似度
- 每張小圖代表模型的**不同層**：QKV（attention）、Proj（投影層）、MLP L1（MLP 第一層）、MLP L2（MLP 第二層，也就是 GELU 之後那層）
- 上排是分類任務 (CLS)，下排是深度估計 (MDE)
論文還做了一個有趣的分析：把「加總壓縮」跟真正最優的更新方向（PCA 主成分）做相似度比較，發現：

- 大部分層（QKV、投影層等）相似度都偏低
- 但 **ViT 的第二個 MLP 層**（也就是 GELU 激活函數之後的那層）相似度明顯較高
- ![[Pasted image 20260907213133.png]]

原因是 GELU/ReLU 這類非線性函數會把特徵推向「正象限」，這正好讓「全部特徵相加」這個固定方向（也就是向量 1）跟真正需要學的更新方向比較接近，不容易正交、也就不太會把有用訊號抵銷掉。

**簡單講**：LoRA 是「有意識地選 attention 層」；1LoRA 是「因為夠省，乾脆全鋪」，而且鋪在 MLP 層（尤其是 GELU 後面那層）反而還特別有效，這也是它能超越 LoRA 的原因之一。


**流程**：完整微調（full fine-tuning）的更新矩陣 → PCA 拆成一堆「重要方向」，依重要性排序 → 拿三種候選壓縮方向（加總 / 隨機 / LoRA 學出來的）各自跟每個主成分算「餘弦相似度」，看誰比較「對得上」。

## 上述問題有特別的經驗能學習嗎
### 1. 「參數少 ≠ 記憶體省」——1LoRA 論文自己在文中提醒

> "Note that parameters are only a proxy for memory consumption, which can be higher depending on **computational graph complexity**."

論文的氣泡圖裡參數量（氣泡大小）跟記憶體使用率（橫條圖）常常對不上：

- **DoRA** 在圖像生成實驗直接 **OOM**（out of memory），因為它算法本身要維護 magnitude + direction 分解，計算圖比參數量顯示的更吃資源
- **MoRA** 雖然參數量能調到跟 1LoRA 一樣少，但因為要做「特徵分組加總」再「複製回原形狀」這種操作，計算和記憶體效率反而不好

**經驗**：評估 PEFT 方法不能只看 trainable parameters 這個數字，要實測記憶體和訓練時間。

### 2. 硬堆更多技巧不一定更好（Ablation 裡的反直覺結果）
![[Pasted image 20260908115615.png]]
論文把 BitFit + DiffFit + 1LoRA 所有組合都試過（Figure 8, Figure 10），結論是：

- 只有「1LoRA + 正規化層(norms)」這個組合值得用
- 其他組合「do not seem to bring additional performance gains, and only slow down the fine-tuning process」

**經驗**：多個 PEFT 技巧疊加會直覺覺得更強，但實際上參數越多、優化難度可能越高，值得先做窮舉消融再下結論，而不是預設「疊加=更好」。

### 3. LoRA 原論文也踩過的坑：更多參數反而效果下降
![[Pasted image 20260908115906.png]]

原始 LoRA 論文的 Figure 2 明確指出：

- prefix-embedding tuning 超過 10^6 個特殊 token 之後效能明顯下滑
- prefix-layer tuning 超過 10^7 個 token 也一樣

作者猜測是「特殊 token 太多，讓輸入分佈偏離預訓練資料分佈太遠」。

**經驗**：不是所有 PEFT 方法都「參數越多、效果越好」的單調關係，這點跟一般直覺（更多可訓練參數=更強表達力）相反，做實驗時務必掃過整個參數量的範圍，不能只測一個點就下結論。

### 4. 「學習」不一定比「固定」好——過度設計的陷阱

1LoRA 用固定的加總向量（不用學）取代 LoRA 那種要學的低秩矩陣。附錄 B.2 比較了「固定加總」vs「隨機向量」壓縮，結果**兩者效果幾乎一樣**，加總只是稍快一點。5.2 節的 PCA 分析也顯示，學出來的方向只比固定方向好一點點，卻要雙倍參數、更多記憶體。

**經驗**：在下手設計「可學習模組」之前，先驗證問題本身是否真的需要學習——如果一個簡單的固定啟發式就能達到 95% 效果，花參數去學那多出來的 5% 可能不划算。

### 5. 直覺假設要驗證，不能只憑理論就上

1LoRA 選「加總（1 向量）」的理由是「ReLU/GELU 會把特徵推向正象限，所以加總方向應該跟重要更新方向接近」。但 PCA 分析（Figure 9）證實：**這個假設只在剛好接在 GELU/ReLU 之後的層成立**（例如 ViT 的 MLP 第二層），其他層（QKV、投影層、MLP 第一層）相似度普遍偏低。

**經驗**：作者誠實地把這個假設的適用範圍寫清楚，沒有過度推廣。這是個好習慣——你的方法有效，不代表你當初的理論解釋涵蓋了全部情況，要拿實驗（這裡是 PCA）去反查理論假設的邊界。

### 6. 反直覺的校準結果，別急著下結論

附錄 B.3 提到一個意外發現：**全微調的誤差分布反而比低秩 PEFT 方法更「重尾」（heavy-tailed）**，也就是全微調偶爾會出更誇張的離群誤差。作者自己也說這跟預期相反（"Contrary to expectation"），而且校準（calibration）上的改善「非常微小」，沒有過度誇大這個發現。

**經驗**：報告反直覺結果時保持謹慎的措辭，不要因為結果support了自己方法就過度解讀成「PEFT比全微調更穩健」這種強結論。

### 7. LoRA 原論文的工程細節：初始化和 scaling 很關鍵

- B 矩陣初始化為 0， A 用高斯分布初始化 → 保證訓練一開始 ΔW=0，不會一開始就破壞預訓練模型
- 用 α/r做 scaling，這樣換不同 rank 時不用重新調 learning rate

**經驗**：這種「工程小細節」往往是論文正文一句話帶過、但沒做對就會讓復現實驗失敗的地方，讀論文時值得特別留意初始化策略。

### 8. Rank 越高不代表學到更多有用資訊

LoRA 論文用子空間相似度（Grassmann distance）分析發現：r=8 跟 r=64學出來的方向，只有前幾個奇異向量方向重疊，其餘方向基本是雜訊。

**經驗**：增加參數預算之前，先確認「多出來的容量」是不是真的被拿去學有用的東西，還是只是在放大雜訊/過擬合。
